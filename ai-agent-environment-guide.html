前回のガイドで解説したように、AIエージェントは「チャット型AI」とは別物であり、 ファイルの読み書き・メールの操作・コードの実行など、自律的に幅広い操作を実行できます。

しかし、「リスクがあるから使わない」という選択肢は現実的ではありません。 AIエージェントを適切な環境で使えば、NPOの業務効率は飛躍的に向上します。

このガイドでは、リスクを最小限にしながらAIエージェントを安全に活用するための環境整備を、 具体的な手順とともに解説します。

まず知っておくべき3つの基本原則

環境整備の具体策を学ぶ前に、AIエージェントの安全管理の土台となる考え方を理解しておきましょう。 これを押さえておくと、「なぜそうするのか」が納得できます。

🛡️ AIエージェント安全利用の3原則

  • 1
    最小権限の原則（Least Privilege）
    AIエージェントに与える権限は、「その作業に必要な最小限のみ」にする。 読み取りだけでいい場合は書き込み権限を与えない。 使い終わったら権限を切る。これだけで大半のリスクが消えます。
  • 2
    アカウント分離の原則（Account Separation）
    「組織共有アカウント」と「AIエージェントを動かすアカウント」を絶対に混在させない。 AIエージェントは専用のアカウント・専用のフォルダの中だけで動かす。
  • 3
    人間確認の原則（Human in the Loop）
    AIエージェントに「全部お任せ」はしない。 重要なアクション（メール送信・ファイル削除・外部への書き込み）は 必ず人間が事前に確認してから実行させる。
💡
この3原則があれば、ゼロリスクでなくてもいい

AIエージェントのリスクをゼロにすることはできません。 しかしこの3原則を守るだけで、リスクの80〜90%は対処できます。 「完璧な準備ができるまで使わない」より「原則を守りながら少しずつ使い始める」方が賢明です。

アカウント設計：個人・組織・AI専用を分ける

AIエージェントを安全に使うための最重要ステップは、アカウントの分離です。 多くのNPOでは「組織の共有Googleアカウント」で全員がログインしているケースがありますが、 この環境でAIエージェントを動かすのは危険です。

推奨するアカウント構成

アカウントの種類 用途 AIエージェント利用 例
組織共有アカウント 公式メール・共有Drive・組織カレンダーの管理 🚫 禁止 info@〇〇npo.org
スタッフ個人アカウント 個人業務・通常のチャットAI利用 ⚠️ チャット型のみ可 yamada@〇〇npo.org
AI専用アカウント
（推奨）		 AIエージェント専用。接続範囲を限定したGoogleアカウント ✅ 推奨 ai-agent@〇〇npo.org
または個人Gmailアカウント
🚨
「組織アカウントでログインしたままClaude Codeを使う」は最も危険

組織の共有Googleアカウントでブラウザにログインした状態でClaude CodeにGoogle DriveのMCPを接続すると、 組織全体のドライブ・メール・カレンダーにAIエージェントがアクセスできてしまいます。 支援記録・財務データ・理事会資料など、機密情報が全て対象になります。

AI専用アカウントの作り方（Google）

  1. AI作業専用のGoogleアカウントを作成する
    個人のGmailアカウント（例：yamada.ai.work@gmail.com）を新規作成します。 組織のGoogle Workspaceアカウントがある場合は、管理者に「AI作業専用サブアカウント」を 作成してもらうことも可能です（例：ai-work@〇〇npo.org）。
  2. そのアカウント専用のGoogle Driveフォルダを作る
    AI専用アカウントのGoogleドライブに「AI作業フォルダ」を作成します。 このフォルダ以外には何もファイルを置かないことがポイントです。 AIエージェントが見れるのは「このフォルダの中だけ」という状態を作ります。
  3. 必要なファイルだけを「共有」で渡す
    AIに処理させたいファイルは、組織の共有ドライブからAI専用アカウントのフォルダへ 「コピーして共有」します。 「閲覧者のみ」権限で共有することで、AIが元のファイルを書き換えられないようにします。
  4. 作業が終わったら共有を解除する
    処理が終わったファイルの共有を解除します。 AI専用アカウントのドライブには、常に必要最小限のファイルだけが入っている状態を保ちます。
✅
小規模NPOへの現実的な代替案

「専用アカウントを作るのが大変」という場合は、 AIエージェントを動かすパソコンに、専用の別ユーザーアカウント（Windows/Mac）を作る方法も有効です。 そのユーザーでは組織アカウントにログインしない、という運用だけでもリスクを大幅に下げられます。

フォルダ設計：AIエージェントの「作業範囲」を限定する

Claude Codeなどのエージェントは、「起動したフォルダ（作業ディレクトリ）」を中心に動きます。 そのため、AIエージェント専用の作業フォルダを作り、そこだけを作業対象にする設計が重要です。

推奨フォルダ構成（ローカルPCの場合）

📁 推奨フォルダ構成
デスクトップ/
├── AI作業フォルダ/          ← Claude Code はここで起動する
│   ├── CLAUDE.md            ← AIへの行動ルール（後述）
│   ├── input/               ← AIに処理させたいファイルを置く場所
│   │   └── （作業ファイルをここにコピー）
│   ├── output/              ← AIが生成したファイルが出てくる場所
│   │   └── （AIの出力物）
│   └── temp/                ← 一時作業用（定期的に削除）
│
├── 組織共有フォルダのショートカット  ← AIフォルダの外に置く
│   └── （組織のファイル本体はここ。AIは触らない）
└── 個人作業フォルダ/              ← AIフォルダの外
    └── （プライベート・重要書類）
⚠️
「デスクトップ全体」や「ドキュメントフォルダ」でClaude Codeを起動しない

広い範囲でエージェントを起動すると、意図しないファイルへのアクセスや変更が起こりやすくなります。 必ず専用フォルダ内で起動することを習慣にしてください。

ファイルの流れ：組織フォルダ→AI→出力の分離

❌
やってはいけない運用
組織の共有ドライブに直接アクセスさせ、AIが元のファイルを直接編集する。 どのファイルが変更されたか把握できなくなる。
✅
推奨する運用
① 元ファイルをinputフォルダにコピー → ② AIが処理してoutputフォルダに保存 → ③ 人間が確認して組織フォルダに取り込む。 元のファイルは一切変更されない。

Googleドライブを使う場合の設計

フォルダ 権限設定 目的
📁 AI-INPUT AI専用アカウントに「閲覧者」権限 AIに読ませたいファイルを一時的に置く。AIは読むだけで書き込めない
📁 AI-OUTPUT AI専用アカウントに「編集者」権限 AIが生成したファイルを置く場所。人間が確認後に組織フォルダへ移動
📁 組織機密フォルダ AI専用アカウントには権限なし 財務・支援記録など。AIは絶対に見られない状態にする

CLAUDE.mdによるClaude Codeの行動ルール設定

CLAUDE.mdは、Claude Codeが起動時に必ず読み込む設定ファイルです。 ここに「してはいけないこと」「必ず確認すること」を書いておくことで、 AIエージェントの行動を事前にコントロールできます。 NPO向けの安全運用において、最も効果的な対策の一つです。

NPO向け CLAUDE.md テンプレート

📋
使い方

AI作業フォルダの直下に「CLAUDE.md」という名前でファイルを作成し、 以下の内容をコピー＆ペーストしてください。 【】の部分は自団体の情報に書き換えてください。

📄 CLAUDE.md — NPO向けテンプレート
# 【団体名】AI作業環境 — 利用ルール

## あなたの役割
あなたは【団体名】のスタッフをサポートするAIアシスタントです。
このフォルダ内の作業のみを支援してください。

## ⛔ 絶対にしてはいけないこと
- このフォルダ（AI作業フォルダ）の外にあるファイルを読み取ること
- このフォルダの外にあるファイルを変更・削除・移動すること
- 個人情報（氏名・住所・電話番号・メールアドレス）を含む情報を外部に送信すること
- 支援対象者・受益者に関する情報を処理の対象にすること
- メール・カレンダーなど外部サービスへの書き込みを確認なしに行うこと
- ファイルの削除を確認なしに実行すること

## ✅ 必ず確認してから実行すること
- ファイルを新規作成・上書き保存する前に、内容を提示して確認を求めること
- 外部APIやWebにアクセスする前に、目的と送信内容を説明すること
- 複数ステップの作業を行う前に、全体の手順を提示して承認を得ること

## 📁 作業対象フォルダ
- input/ ← 処理対象ファイル（読み取りのみ）
- output/ ← 生成物の保存先
- temp/   ← 一時作業用（重要ファイルは置かない）

## 🚫 AIに入力してはいけない情報
- 支援対象者の氏名・住所・連絡先・相談内容
- DV・虐待・生活困窮に関する個人情報
- スタッフの個人連絡先
- 財務詳細データ（口座番号・詳細な経理情報）
- 未公表の事業計画・契約情報

## その他の注意事項
- 数値・統計を引用する際は必ず出典を明記すること
- 生成した文章に「AI生成」であることを示すコメントを付けること
- 不明点があれば作業を進める前に確認すること

CLAUDE.mdを効果的にするコツ

📌
禁止事項は具体的に書く
「個人情報を扱わないこと」より「氏名・住所・電話番号・支援記録を処理しないこと」の方が効果的。 AIは具体的な指示ほど正確に従います。
🔄
定期的に見直す
業務内容や使うツールが変わったら、CLAUDE.mdも更新します。 3ヶ月に1回は内容を見直す習慣をつけましょう。
👥
チームで内容を共有する
CLAUDE.mdの内容をスタッフ全員で確認し、「なぜこのルールがあるか」を共有します。 ルールの背景を理解することで、類似の状況でも適切に対応できます。
🏢
プロジェクトごとに作る
助成金申請用・広報用など、用途別に専用フォルダとCLAUDE.mdを作ることで、 それぞれの業務に適したルールを設定できます。

MCPツール接続の権限管理

MCP（Model Context Protocol）とは、Claude Codeと外部サービス（Google Drive・Gmail・GitHubなど）を つなぐ仕組みです。便利な反面、接続する権限の範囲が広すぎると、AIが意図しない操作を行うリスクが高まります。

MCPツール別：推奨権限設定

MCPツール 使っていい権限 原則禁止の権限 注意点
Google Drive 指定フォルダの読み取り・ファイル作成（output専用フォルダのみ） 組織共有ドライブ全体への書き込み・削除 AI専用アカウントで接続。組織アカウントでは接続しない
Gmail 下書き作成・メール検索・読み取り メール送信・連絡先へのアクセス 「下書き作成のみ」スコープで認証する。送信は必ず人間が行う
Google Calendar 予定の読み取り・下書き作成 予定の自動作成・招待状の送信 共有カレンダーへの書き込み権限は与えない
GitHub コードの読み取り・Issue作成 本番ブランチへの直接プッシュ・Secrets閲覧 作業用のフォーク・ブランチのみ操作可能にする
Slack メッセージの下書き作成・チャンネル読み取り メッセージの自動送信・DM送信 送信はすべて人間が確認してから行う

MCP接続の「つけ外し」を習慣にする

  1. 使う直前にMCPを接続する
    「Google Driveで文書整理をするから今日だけ接続」という形で、 常時接続したままにしない。Claude Codeの設定から、使う時だけ有効にする。
  2. 作業が終わったらすぐ切断する
    作業が完了したらMCPの接続を解除する。 Claude Codeを閉じるだけでなく、接続設定からも確認して無効化する。 「つけっぱなし」が事故の元です。
  3. 接続内容をログに残す
    「いつ・誰が・どのMCPを・何の作業で使ったか」を簡単なメモで記録しておく。 月1回程度振り返ることで、不審な利用を早期に発見できます。
🔑
OAuth認証スコープの確認が重要

MCPを接続する際にGoogleアカウントの認証画面が出ます。 そこに表示される「アクセスの許可」の内容を必ず確認してください。 「Gmailのすべてのデータへのアクセス」など広すぎる権限が求められる場合は、 そのツールの利用を見直すか、別の方法を検討してください。

6

モニタリング：何が起きたか定期的に確認する

どれだけ準備をしても、予期しないことは起こりえます。 重要なのは「何かあったとき早く気づける」仕組みを作ることです。 モニタリングは難しくありません。月1回、10分の確認で十分です。

確認すべきログと確認方法

確認項目 確認場所 確認頻度 チェックポイント
Googleアカウントのアクティビティ Googleアカウント →「データとプライバシー」→「アクティビティ管理」 月1回 知らないアプリからのアクセス・不審なログイン場所がないか
Google Driveのアクセス履歴 GoogleドライブのファイルをD右クリック→「バージョン履歴」または「詳細パネル」 月1回 意図しないファイルの変更・削除がないか
Google連携アプリの確認 Googleアカウント →「セキュリティ」→「サードパーティアプリとサービス」 3ヶ月に1回 不要になったMCP接続・アプリが残っていないか。不審なアプリを削除
Claude Codeのプロジェクト履歴 Claude Code上の会話履歴 週1回（使った週のみ） 意図しない操作の指示・実行がなかったか確認
outputフォルダの内容 ローカルのoutputフォルダ 作業後すぐ 生成されたファイルが想定内の内容かを確認してから組織フォルダに移す

異常を発見したときの対応手順

  1. すぐにMCP接続をすべて切断する
    Claude Codeの接続設定からすべてのMCPを無効化する。 Googleアカウントの「サードパーティアプリとサービス」からも接続を削除する。
  2. 影響範囲を確認する
    どのファイルにアクセスされたか、どのメールが閲覧されたかをログで確認する。 変更されたファイルがあれば、Googleドライブの「バージョン履歴」から復元できます。
  3. 関係するスタッフに報告する
    個人情報を含む可能性のある情報にアクセスがあった場合は、 事務局長・理事長に報告する。必要に応じて個人情報保護委員会への報告も検討する。
  4. 再発防止策を検討して記録する
    「何が原因でどんな問題が起きたか」「次はどう防ぐか」をCLAUDE.mdまたは 組織のルール文書に追記する。インシデントを学びに変える。

まずA4・1枚で十分。完璧より「あること」が大切

完璧なポリシーを作ろうとして何ヶ月もかけるより、 シンプルでもいいので「ルールが存在すること」が重要です。 スタッフが読んで理解できる長さに収めましょう。 コミュニティで他の団体の事例を共有しながら、少しずつ改善していきましょう。

環境整備チェックリスト

このチェックリストで、自団体の環境整備の状況を確認しましょう。

🔑 アカウント設計
  • 組織共有アカウントではAIエージェントを使わないルールを決めた
  • AI作業専用のアカウントまたはパソコンユーザーを作成した（または検討した）
  • スタッフ全員に「組織共有アカウントでのAIエージェント禁止」を周知した
📁 フォルダ設計
  • AI作業専用フォルダを作成した（input / output / temp の構造）
  • AIエージェントはAI作業フォルダ内のみで起動するルールを決めた
  • 機密情報を含むフォルダはAIエージェントからアクセスできない設定にした
📄 CLAUDE.md
  • AI作業フォルダにCLAUDE.mdを作成した
  • 「入力してはいけない情報」を具体的にリストアップした
  • 「確認なしに実行しないこと」をCLAUDE.mdに明記した
  • CLAUDE.mdの内容をスタッフで確認・共有した
🔌 MCP権限管理
  • 接続しているMCPツールとその権限範囲を把握している
  • Gmail・Google DriveのMCPは「下書き・閲覧のみ」など最小権限で接続している
  • 使い終わったMCPはその都度切断する習慣ができている
  • Googleアカウントの「サードパーティアプリ」リストを確認した
📊 モニタリング・ポリシー
  • Googleアクティビティの月次確認を担当者に割り当てた
  • 組織のAIエージェント利用ポリシーを文書化した（または予定がある）
  • インシデント発生時の報告先・対応手順を決めた
